# Regression Environment — Config as Code

Terraform configuration **managing** the static PingOne regression environment
used by the PR regression workflow (`.github/workflows/regression.yaml`) and
`tests/regression/run-local.sh`. If the live environment drifts or is lost,
`terraform apply` from this directory converges it back — locally, or via the
`regression-env-apply` GitHub Actions workflow (see `tests/regression/README.md`
for the drift-repair runbook and the new-resource checklist).

State lives in the S3 backend (values supplied at `terraform init` from the
CI secrets). Variable values are **not committed** — they ride in the
`TERRAFORM_TFVARS_BASE64` CI secret (the exported tfvars file, base64-encoded)
and 1Password.

## Layout

Originally generated by `pingcli-terraformer export --output-format hcl
--include-values`, then reviewed, scrubbed, and hand-maintained since:

```text
versions.tf                        # required providers + empty backend "s3" (values at init)
ping-export-module.tf              # root module block wiring variables into ping-export-module/
ping-export-variables.tf           # variable declarations (root)
ping-export-module/                # child module: one .tf per resource type
```

Snapshot taken 2026-09-01 with the exporter at commit `c14d0b5` (includes the
label-identity fixes from PR #146). Contents: 198 resources across 7 types —
3 applications, 19 application flow policies, 26 connector instances, 35 flows
(+ 35 each of flow_deploy/flow_enable), 45 variables.

New resources are added **by hand** (see the checklist in
`tests/regression/README.md`) — do not re-export over this directory; re-exports
would clobber lifecycle blocks and hand-authored entries. To diff the live
environment against this config, re-export into a scratch directory and compare.

## Secrets handling

- Connector `clientSecret` fields and other API-recognized secrets are empty in
  this config — the PingOne/DaVinci API does not return secret values on read.
  Secret-bearing connector instances carry
  `lifecycle { ignore_changes = [properties] }` so **apply can never overwrite
  the live secrets with empty values**. To intentionally change a connector's
  non-secret properties, temporarily remove that instance's `lifecycle` block,
  and re-enter its secrets from 1Password afterwards.
- `davinci_variable_testPW_value` is a real password (held in 1Password and
  the `TERRAFORM_TFVARS_BASE64` CI secret) stored in a plain (non-secret)
  DaVinci variable. It is declared
  `sensitive` with no default — `terraform plan` fails until it is supplied via
  `TF_VAR_davinci_variable_testPW_value`, the tfvars file, or `terraform.tfvars.json`) locally.
  It must never be committed here. It is also embedded in three flow
  definitions' rich-text nodes (`DaV-Flow-postman`, `DaV-Flow_1775670546`, and
  its clone) as `<REDACTED-SET-VIA-UI>` — repairs that recreate those flows
  require re-entering the value.
- Four flows with genuinely empty descriptions in the live environment
  (`DuplicateName`, `flowContextVariable`, `pingoneFormsTest`,
  `testCodeSnippetConnector`) have `description = ""` **omitted**: the
  `pingidentity/pingone` provider enforces min-length 1 on flow descriptions,
  so the exporter's verbatim rendering produces HCL that fails `terraform
  validate`. This is a known exporter gap — the exporter should omit empty
  optional strings for provider-validated attributes. After state adoption,
  these resources may need `lifecycle { ignore_changes = [description] }` (see
  "Adopting state"). Re-exporting reproduces the invalid attribute until the
  exporter is fixed.

## Regenerating (scratch only)

Wholesale re-export over this directory is **retired** — the config is the
source of truth for the managed environment, and re-exports clobber lifecycle
blocks and hand-authored resources. Two helpers, both run with the read-only
credential item `op://PingIdentity/terraformer-export-regression-read-only-US`
(see `.scratch/op-terraformer-export-env-read-only-US.env` template — that
file is git-ignored):

```bash
# Refresh ONLY the tfvars values file (full export to a temp dir, only the
# tfvars file is copied here — committed .tf files untouched).
op run --env-file=.scratch/op-terraformer-export-env-read-only-US.env -- \
  ./export.sh

# Wholesale refresh: back up the committed config, then replace the .tf files
# with a fresh full export (use when the environment's resource set changed,
# e.g. after deliberate UI adjustments). Review the git diff before
# committing; revert with ./export.sh --revert.
op run --env-file=.scratch/op-terraformer-export-env-read-only-US.env -- \
  ./export.sh --full

# Same as --full, plus the one-time state-adoption import file (see
# "Adopting state").
op run --env-file=.scratch/op-terraformer-export-env-read-only-US.env -- \
  ./export.sh --full --imports
```

Default mode exports to a temp dir and copies only the tfvars file here —
the committed `.tf` files are never touched. `--full` replaces them (after
backing the tracked config up to git-ignored `.config-backup/`; `--revert`
restores it).

- **`ping-export-terraform.auto.tfvars` is git-ignored.** Review it (scrub
  anything unintended), keep the master copy in 1Password, and upload it
  base64-encoded as the `TERRAFORM_TFVARS_BASE64` GitHub secret.
- For a local `terraform plan`/`apply`, leave the tfvars file in place (it is
  auto-loaded); for diffing, compare the scratch export's resource files
  against the committed ones.
- An unexpected diff between the scratch export and this config means the live
  environment drifted — repair it with the `regression-env-apply` workflow
  (config is authoritative), not by copying exported files here.

## Adopting state (one-time)

The live environment's 198 resources must be imported into the S3 state before
the first apply. This is a maintainer task done **locally** (import only reads
— the read-only credential is sufficient), using import blocks the exporter
generates in exactly the right `module.ping-export.<type>.<label>` address
format:

```bash
make build

# 1. Generate the import blocks (throwaway export; addresses match because
#    module name/dir are the exporter defaults).
op run --env-file=.scratch/op-terraformer-export-env-read-only-US.env -- \
  ./pingcli-terraformer export --output-format hcl --include-imports \
  --out /tmp/env-import --module-name ping-export --module-dir ping-export-module

# 2. Copy ONLY the import file into this root module (it is git-ignored).
cp /tmp/env-import/ping-export-imports.tf .

# 3. Init with the real backend and provide variable values — locally,
#    easiest as the git-ignored ping-export-terraform.auto.tfvars generated
#    by ./export.sh (contains testPW too).
terraform init \
  -backend-config="bucket=${TF_VAR_tf_state_bucket}" \
  -backend-config="region=${TF_VAR_tf_state_region}" \
  -backend-config="key=terraform.tfstate" \
  -backend-config="encrypt=true"

terraform plan -out=adopt.tfplan    # review; expect near-zero diffs

# 4. Apply — import blocks are consumed during apply.
terraform apply adopt.tfplan

# 5. Remove the import file and confirm a clean plan.
rm ping-export-imports.tf
terraform plan                      # must show "No changes."
```

**Iterate perma-diffs before the first apply.** Anything that diffs on every
plan gets a targeted `lifecycle { ignore_changes = [...] }` with a comment
explaining why — expected candidates: the four empty-description flows
(`ignore_changes = [description]`), and API-normalized flow attributes.
`flow_deploy`/`flow_enable` stay un-ignored initially (their
`deploy_trigger_values` derive from the config's flow definitions); if plans
show version churn on unchanged flows, add
`ignore_changes = [deploy_trigger_values]` and treat flow deployment as a
manual checklist step.

Local plan/apply runs need the write-scoped worker creds
(`PINGONE_CLIENT_ID`, `PINGONE_CLIENT_SECRET`, `PINGONE_ENVIRONMENT_ID`,
`PINGONE_REGION_CODE` env vars) and the tfvars values — the same payloads as
the two repo-level CI secrets (`TERRAFORM_PROVIDER_ENV_BASE64` +
`TERRAFORM_TFVARS_BASE64`).

## State and apply policy

- State lives in S3 (`regression-environment/terraform.tfstate` key), shared
  between local maintainer runs and the `regression-env-apply` workflow. Never
  commit state, plans, or the import file — all are git-ignored here.
- Applies happen through the `regression-env-apply` workflow (manual dispatch,
  reviewer-gated) or locally by a maintainer. No schedule, no PR automation.
- To rebuild the environment from scratch after total loss: `terraform apply`
  into a new empty PingOne environment, then update the GH `regression`
  environment secrets (`PINGCLI_PINGONE_EXPORT_ENVIRONMENT_ID` and connector
  envId properties) to point at the new environment ID, and update
  `pingone_environment_id` in the variable values blob.
