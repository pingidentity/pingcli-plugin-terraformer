# Regression Environment — Config as Code

Terraform configuration describing the **static PingOne regression environment**
used by the PR regression workflow (`.github/workflows/regression.yaml`) and
`tests/regression/run-local.sh`. This directory is the rebuildable baseline for
that environment: if it is ever lost or drifts, recreate it from here.

**Do not modify the live regression environment** — changes to it cause false
positives in regression comparisons. To change the environment intentionally:
update it via this config in a scratch environment first, re-export, review,
and commit — never by hand in the PingOne admin console.

## Layout

Generated by `pingcli-terraformer export --output-format hcl --include-values`,
then reviewed and scrubbed:

```text
ping-export-module.tf              # root module block wiring variables into ping-export-module/
ping-export-variables.tf           # variable declarations (root)
ping-export-terraform.auto.tfvars  # exported values; secrets emptied (see below)
ping-export-module/                # child module: one .tf per resource type
```

Snapshot taken 2026-09-01 with the exporter at commit `c14d0b5` (includes the
label-identity fixes from PR #146). Contents: 198 resources across 7 types —
3 applications, 19 application flow policies, 26 connector instances, 35 flows
(+ 35 each of flow_deploy/flow_enable), 45 variables.

## Secrets handling

- Connector `clientSecret` fields and other API-recognized secrets export as
  `""  # Secret value - provide manually` — the PingOne/DaVinci API does not
  return secret values on read, so a rebuild requires re-entering them by hand
  (from the team's credential store) and re-deploying the affected flows.
- `davinci_variable_testPW_value` was **manually scrubbed** on 2026-09-01: it is
  a password stored in a plain (non-secret) DaVinci variable that the exporter
  legitimately extracted. The same value was redacted from the three flow
  definitions that embed it in a rich-text node (`DaV-Flow-postman`,
  `DaV-Flow_1775670546`, and its clone). Placeholder: `<REDACTED-SET-VIA-UI>`.
  If you rebuild the environment, set this variable through the DaVinci UI (or
  1Password) — never commit it here.
- Four flows with genuinely empty descriptions in the live environment
  (`DuplicateName`, `flowContextVariable`, `pingoneFormsTest`,
  `testCodeSnippetConnector`) had `description = ""` **omitted**: the
  `pingidentity/pingone` provider enforces min-length 1 on flow descriptions,
  so the exporter's verbatim rendering produces HCL that fails `terraform
  validate`. This is a known exporter gap — the exporter should omit empty
  optional strings for provider-validated attributes. Re-exporting reproduces
  the invalid attribute until that is fixed.

## Regenerating

Prerequisites: 1Password CLI signed in, item
`op://PingIdentity/terraformer-export-regression-read-only-US` (see
`.scratch/op-terraformer-export-env-read-only-US.env` template — that file is
git-ignored).

```bash
make build   # or: go build -o ./pingcli-terraformer .
op run --env-file=.scratch/op-terraformer-export-env-read-only-US.env -- \
  ./pingcli-terraformer export \
    --output-format hcl \
    --include-values \
    --out tests/regression/environment/
```

After regenerating:
1. Re-scan for credential-shaped values before committing (the automated
   secret detection covers connector secrets, but **plain DaVinci variables
   holding passwords are not flagged** — audit `*_value = "..."` lines by eye).
2. Re-apply the scrub for `testPW` (and any other manually-held credentials).
3. Diff against the committed version: unexpected resource additions/removals
   mean someone modified the live environment (which should not happen — see
   above).

## State and apply policy

This config is a **baseline, not a management tool**. There is no Terraform
state for it in CI, and it is never applied to the live environment. Use:

- `terraform -chdir=tests/regression/environment/ping-export-module plan` with a
  filled tfvars file if you want to see drift against the live environment
  (requires `terraform import`ing resources into a throwaway state first).
- To rebuild the environment from scratch after loss: `terraform apply` into an
  empty PingOne environment, then update the GH `regression` environment
  secrets (`PINGCLI_PINGONE_EXPORT_ENVIRONMENT_ID` and any connector env IDs)
  to point at the new environment ID.
